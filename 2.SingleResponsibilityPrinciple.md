### What is Single Responsibility Principle (SRP)?
It says that a class should have only one reason to change. It doesn't mean that it can have only one function. It means that it should handle a single responsibility and that responsibility is teh only reason to change the class.

### What is meant by the "reason to change"?
Imagine we have an Order class:

``` cpp
class Order {
public:
    void calculateTotal();
    void saveToDatabase();
    void sendEmail();
    void generateInvoice();
};
```

At first glance, this might look convenient. Everything related to an order is in one place.
But now think about why this class could change:

- The pricing team changes how the order total is calculated.
- The database team changes how orders are stored.
- The notification team changes how emails are sent.
- The billing team changes the invoice format.

The solution would be to separate these individual responsibilities to individual classes:
``` cpp
class Order {
public:
    void calculateTotal();
};

class OrderRepository {
public:
    void save(Order order);
};

class EmailService {
public:
    void sendEmail(Order order);
};

class InvoiceGenerator {
public:
    void generateInvoice(Order order);
};
```
Now if the format of invoice generation changes, we won't be touching the Order class, as it doesn't care about the invoice or its format.

Now the confusion could be that all of the things (sending the email of the order, generateing the invoice for the order and saving the order into the DB) are related to the order only, so they must be handling the same responsibility and must be kept in the same class. 

The point is that being related to the same entity does not mean they have the same responsibility.

### Why do we even have SRP?
- Because SRP helps in reducing coupling: One change could affect a huge amount of unrelated functionalities
